## Decisions

**The import page stays a fetch-driven page.** The common brief's "every answer is a 303" is for form posts; this page reads files in the browser and talks to the import ops over REST, so there is no reloadable POST. What the brief protects is kept: a reload repeats nothing (the answer after an apply is page state, not an address), the person's file stays chosen after a refusal or a busy answer, and a change the server refuses is taken back. The Editions page's only action, the download, is a GET that answers a file or a 303 with a single-use flash (`flash.go`).

**After an apply that kept an edition, wrote suggestions or comments, the page does not navigate.** It replaces the chooser with the result, focused and at the top, because a person has to be told where the original went and where the suggestions wait. The label shown is read back with `edition.get`. An import with none of these keeps the old behaviour (straight to the first document), so the existing scripts and habits are unchanged.

**A merge stands alone and a move leaves the order lists.** The backend refuses a join with any other field on the same edit, and refuses an order that names a child a parent no longer has. The page replaces a key's edits with the join and removes a joined or moved key from every order list before the next preview. Joins are remembered like left-out chapters, so they can be undone ("Put back"). A change the server still refuses (422, 409) is rolled back to the last state the server accepted (kept per preview request, not per click, because previews wait 350 ms and two changes can be inside the wait), with the server's sentence and "That change was not made."

**Pickers are lazy.** "Nest under" and "Join into" build their list of targets when opened, one select at a time, with an explicit button (a select that acts on change would move chapters while a person arrows through it). Targets exclude the chapter and everything inside it, which are the cases the server refuses. A book of 2,000 documents never builds 2,000 lists.

**The report is not dumped.** The generic "what the converter read" list flattens one level, so `report.pdf.report` and `report.docx.tracked` would read as keys. For PDF and Word the page draws its own panel from the structured report, with the words in the catalogue and a mark plus words for each limit, and folds the server's own English sentences under "Everything the importer noted".

**Only an EPUB is an edition.** The screens say the original is kept for an EPUB only; for a PDF they say only its checksum is recorded. No Editions row is made for Word or PDF.

**Words.** The words of the existing import page are still literal English (they were before). Every word added here is in the catalogue and each new screen was looked at under `xx-rtl`. The pre-written `import.epub.*`, `import.pdf.*`, `import.tracked.*` keys the backends left in `en.json` were not what the screens needed (each screen sentence has its counts in the sentence), so they were removed and replaced by `imp.*`, `imp.js.*` and a revised `editions.*`.

**Budgets.** `import.js` 7,336 bytes gzip (cap raised from 6,656 to 7,424: the refused-change rollback, the retry, join and move edits, the hooks); `import-books.js` 8,036 bytes gzip against 8,192 (about a hundred catalogue words with their English defaults, which compress well; the page's three panels); `editions.css` under 1 KB gzip; no script on the Editions pages. `import.css` is 2,155 bytes gzip (it was 1,582). All page CSS stays far under 25 KB.

**Who imported.** `imported_by` is an id; the page names the person through `project.member.list` and says "Someone who is no longer on the project" only when that list was read and lacks the id. When the list cannot be read the row is left out rather than saying something untrue. `source_name` is in the edition's own record only: the mirror, the export manifest and a Git push write explicit fields (`export.EditionMeta`), and a test asserts the name is not in the bundle's manifest.

## Backend change (additive)

`recordEdition` writes `source_name` (the name the import was given, cleaned and cut at 200 characters) into the edition's metadata, so the list can say which file an edition came from. Before this the edition had no file name anywhere (the download is named from the label). One assertion in `TestEpubEditionIsKeptIntactAndMapped`.

## Backend gaps found

1. No edition has a file name field; `source_name` in the metadata is the answer, and an edition made before this change has none (the list then omits the file name).
2. `edition.list` returns `imported_by` as an id; the page turns it into a name through `project.member.list`, which only owners may call, so an administrator who is not a member sees "Someone who is no longer on the project".
3. The refusal for a scan begins with a lower-case letter ("this PDF has no text layer"); the page capitalises refusals it shows.
4. The preview's `epub.files[].key` is the document a file started or continued; the page shows its title and falls back to the title the file gave.

## Round 2: the diff screens (F-996)

Files: `internal/server/editiondiffui.go`, `web/templates/editiondiff.html`, the diff block of `web/static/css/editions.css`, `scripts/e2e-editions-diff.mjs`, the a11y walk entries, `editions.diff.*` words (the backend's pre-written block, reworded and extended; the unused ones removed), Go tests in `editionsui_test.go`. No script and no new JavaScript: every state is a page.

**Pages, not dialogs; actions answer with a 303.** The list and a chapter's differences are GET pages from parameters that only name things (an edition, a chapter's key). Suggesting and putting back are POSTs (`uiRoute`: session and CSRF) that call the op and answer with a 303 to a GET page and one single-use flash (`flash.go`): the sentence is focused (`autofocus`, no script), a reload repeats nothing and does not say it again. A put-back answers with the list, since the steps' keys are not the same after a write; a suggestion answers with the chapter's page again, with what was made and, line by line, what was not and why.

**A guess is shown as one, and a pairing the import recorded is not.** `match.guess` draws a dashed box, a `?` mark, the word "A guess." and the confidence as a percentage, with "Check that these are the same chapter"; the page explains what a guess is under the summary and says the score is not a probability. Between two editions the same file name is a guess (the op says so) and the page follows the op. Words are "added" and "removed", always two figures, never one net figure.

**Confirmation is the op's and the page's.** The put-back section says the text now is saved first as a version, that nothing is lost and that no words count toward goals, and offers an unticked, required box only when the op says the pairing was a guess (`offer.confirm`); a form posted without the box is refused by the op and the page says so (tested, by posting the form without it). The `base_revision` is read from the chapter's document when the page is drawn, after the comparison: a change in between makes the next action stale, never silently overwritten; a stale answer is said in words and the chapter is shown as it is now.

**Text is data.** A hunk's text and every word-diff run are written by `html/template` inside a block with `dir="auto"` and `unicode-bidi: isolate`; the test (`TestTheDiffScreenWritesABooksTextAsText`, and the browser script with a book whose chapter holds `<script>`, `%%private%%`, `[[wiki]]`, `{{.Secret}}` and a direction override) asserts no element comes out of it and no script runs. The importer already escapes such text in the document (`\<script\>`), and the page shows what the document holds.

**Roles.** The list of chapters is for any reader of the project; the text of an edition (a chapter's page, the whole of compare) is for editors, and a reader who asks for a chapter's text by address gets the list and a sentence. The page never looks for a chapter that was left out at import: the op drops it for anyone below editor, and a reader's counts (`edition.get`, `edition.list`, `base.chapters`) are the op's. `edition.compare` is for editors of both projects; the second project is chosen from `project.list` (projects the person owns or edits) and its editions from `edition.list`. A second comparison started while one runs is a 429 the page says calmly, with a Try again link; the browser script provokes a real one with parallel requests.

**Backend facts found.** An instance administrator who is a member of one project and not of another can compare with the other (the op treats an administrator as the owner of every project, as every op does), while the pages answer 404 to an administrator who is not a member (see Round 3, M7).

**Budgets.** No script; `editions.css` is 1,935 bytes gzip and is the only sheet the new pages add to `git.css`.

**Run.** `node e2e-editions-diff.mjs` 22 of 22; `node e2e-a11y.mjs --only edition` 0 violations on 13 pages (the diff, step, reader, picker, compare, compare-step pages among them, both themes, 1280 and 390 px).

## Round 3: the review's findings

A review of the round-1 screens (`review-ui-7-import.md`) found one critical backend defect, three high and a set of medium and low findings. What was done with each:

**C1, critical, fixed in the server.** `applyEdits` filled its skip map as it went, so a merge into a chapter that was also left out was refused when the skip came first and accepted (the merged text silently in no document) when the merge came first. `internal/imports/plan.go` now judges the whole edit set, not each edit in turn: it checks the keys and the documents merged away (no other edit may touch one), makes every move in the book's reading order, then every merge (a chapter after all that are merged into it, so a chain is the same chain in any order, and a loop is refused; text is added in reading order), then titles, kinds and skips, and only then settles the set of chapters left out (a chapter is left out when it or one it is in is) and refuses a merge or a move into one. `TestEpubMappingDoesNotDependOnTheOrderOfTheEdits` runs twelve cases (merge into a skipped chapter, merge of a skipped chapter, into a chapter in a skipped part, into a skipped part, move into a skipped chapter or into a chapter of a skipped part, a chain whose last target is skipped, a loop, a chain, a move into a chapter that is merged away, a merge and a move and a rename, an unrelated skip) in **every order** of the edits and asserts the same answer, the same chapters in the same order, and that the apply agrees with the preview. The contract changed in two small ways, both for the better: a move into a chapter that another edit merges away is now accepted in either order (it was refused when the merge came first), and an edit that names a chapter merged away by any edit of the set is refused whatever its position. The screen prevents the combination too: a chapter that others are joined into cannot be left out until they are put back (and neither can a part that holds it), with the sentence "X cannot be left out while Y is joined into it. Put Y back first."

**H1, fixed.** A chapter with no chapter to join into has the Join control disabled with "There is no other chapter to join this into." (and Nest likewise when there is nowhere else); `act()` ignores a join with an empty or unknown target and says so, so the page's state is the server's: nothing is listed as left out that stays in. **H2, fixed by refusing:** a part, or a chapter with chapters inside it, cannot be joined (the control is disabled with "A part, or a chapter with chapters inside it, cannot be joined. Make it a chapter first, or move its chapters."); the server still moves a merged chapter's children, which the screen simply never asks for, and the left-out list no longer prints a count of chapters "inside" a join. **H3, fixed:** the Edit panel and its picker have `min-width: 0; max-width: 100%`, the tree stops indenting after four levels (the level is said in words in the chapter's line: "level 10"), the Go button wraps; the 390 px script now uses a 36-chapter book with long titles and nests a chapter ten levels deep through the page, and checks 390, 320 and 195 px (200% zoom of a phone), that nothing runs off the screen, every button of the deepest Edit panel is inside the viewport and every control is 44 px at 390.

**M1** after Put back the focus goes to the restored chapter's Edit control. **M2** moves are announced in a region of their own (`#imp-live`, polite, kept 8 s, never touched by the status line) with where the chapter went ("Moved The Wall above The Road: now 1 of 3."; "Moved X to the end of Y."; "Joined X into Y…"), and the status line no longer says "Updating…". **M3** Move to top and Move to bottom (from four siblings up). **M4** the edition's chapter list says "Joined into “X”." for a chapter whose document an earlier chapter went into, and its link says "Open the document it was joined into". **M5** the pairs line names each author as "Name (from a Word file)". **M6** "This book has no cover picture." for a coverless book. **M7, documented, not changed:** the Editions pages, like every project page, find a project through the person's membership, and an instance administrator who is not a member is a stranger to pages (the gate tests assert it, with or without a passphrase); the REST ops treat an administrator as owner. Making these pages an exception would make them the one page family that differs, so the difference is written in OPERATIONS and F-994.

**Lows.** Nested bullets in the tracked-changes reasons (the inner list is its own non-bulleted item); logical properties in `.imp-facts` and `.imp-tree ul` (and the diff and Editions CSS already used them); the option labels of Nest and Join read "Title (in Part)" and not "– Title"; the Join button is 44 px wide; the typed edition label is stripped of direction overrides and control characters in the page and by the server (`recordEdition`, tested through the API); a PDF from which nothing could be read because its parts went over the reader's limits is refused as too complex, not as a scan (`pdfchild.go`, `ErrPDFTooComplex`, tested with the 21 MB hostile file; the reader already knew: `Info.PageTreeProblem` and truncated pages); the Editions list's facts are a short two-column list at 390 px and the chapter rows show the file's own name (the whole path is its title); the three folds that had lost their disclosure triangle have it; Editions is offered to every role that can read the list (it is readable by readers and reviewers), in the project menu, the More list and the palette, and F-994 says so; dead code removed (`hook.msg`, the exported `into`, three unused arguments of `hook.node`, `hook.moved`).

**Stale claims corrected:** the key families the epub and pdfword notes pointed screens at; the script counts; F-988, F-991, F-992, F-994, F-820, F-990 rewritten to what is built.

**`e2e-import.mjs`'s failing step (the project menu's Rebuild).** It passed in nine runs on this branch. The cause of the one failure the reviewer saw is in the test, not the page: htmx swaps the dialog's body and the shell puts the focus back in `htmx:afterSettle` (htmx's 20 ms settle delay); for those 20 ms the focus is on `<body>`, and the check ran the moment the text changed. The step now waits (up to 3 s) for the focus to be back in the dialog, which is what a person's next key press would meet. Not a regression: the page behaviour is unchanged.

**Round 2's diff screens against the same standards.** A 36-chapter book with long titles and one chapter with 200 differences: the list and the differences do not scroll sideways at 390 and 320 px, Next difference moves to the next one, no control is without a name, the sentence after an action takes the focus (`autofocus`), `xx-rtl` and forced colours were already checked, and the CSS uses logical properties. The diff pages are consistent with the Editions pages for administrators (404 for a non-member). The phone sign-in the script used three times met the sign-in rate limit; the script now reuses one phone.

**Budgets.** `import.js` 7,991 bytes gzip against a cap raised to 8,192 (it was 7,336: top and bottom moves, the announcement region, the rule that keeps a join and a left-out chapter apart, the depth word); `import-books.js` 8,782 against 9,216 (disabled controls with their sentences, the announcements, where a chapter went); `import.css` 2,319; `editions.css` 1,606.

## Round 4: the review of the diff screens

No critical finding. What was done:

**H1, fixed by paging.** A chapter's differences are on pages of 50 (`?chapter=KEY&page=N`), with "Differences 51 to 100 of 350", Previous page and Next page above and below. The button now reads "Suggest these N changes", and its form carries the ids of the differences on the page and nothing else (the old "Suggest all of these changes", which also offered the ones the page did not list, is gone). The handler sends at most 20 ids to the op at a time (its limit), so a page is up to three calls; what was made and what was not (counted by reason) is said, and a press that meets the rate limit says how many were made and that pressing again does the rest of the page. The review's test was rewritten for this design (`TestSuggestAllActsOnlyOnTheDifferencesOnThePage`).
**M1, improved in the backend and caveated.** `revisions.DiffWithin` cuts a paragraph that is too long for a word diff at the ends of its sentences and diffs those, so one huge paragraph gives the same counts as the same text in many paragraphs (tested); what still cannot be refined (no sentence ends, or the budget) is counted whole, and the chapter's row and the totals say "counted by whole paragraph".
**M2, fixed.** A flash can carry a scope; the diff pages' sentence is for one project and one edition and is taken only there (`flashTakeFor`); the generic `flashTake` no longer takes a scoped one. **M3, fixed, in a different way:** the redirect goes to the same page and the sentence is drawn beside the difference it is about (or above the list, or in the take section) with the focus on it; a browser does not apply `autofocus` to a page opened at a fragment, so the redirect has no fragment and the focus brings the sentence into view. **M4:** a link "Put this chapter back" at the top of the chapter's page and "Back to the top" at the end. **M5:** one sentence for a second project that is missing, not the person's or locked ("That project cannot be compared with. Check that you are an editor of it and that it is unlocked."); no oracle was added (the three cases give the same page). **M6:** a reworded paragraph over 300 words shows the word-by-word line and folds the two whole texts, closed, with their word counts.
**Lows.** L1 the edition id is checked (`^[A-Za-z0-9_]{1,64}$`, 404 otherwise) and every segment of the redirect is path-escaped; L2 the links to the chapter have a 44 px target; L3 spacing of the take section and the guess box; L4 the signs sit outside the struck or underlined run; L5 the sentences that were glued from fragments (the line under the title, the edition's kind and file name, the status with its flags) are one catalogue string each; L6 a key that is not in the comparison says "That chapter is not in this comparison."; L7 the rate-limit sentence is a polite status, not an alert; L8 titles in the chapter list are isolated with `<bdi>`.
**One change to the keyboard path:** a difference that has a Suggest button no longer has Previous and Next links of its own (Tab goes from one button to the next, and Shift+Tab back); a difference without a button keeps Next. With them a page of 50 had more than 120 tab stops, which the accessibility audit takes for a trap.
**Stale claims corrected:** the script is 22 steps (it was 16), the audit walks 13 pages for `--only edition`, `editions.css` is 1,935 bytes gzip, F-996 states the paging rule, and `editiondiff.md` says the screen does not offer a `dry_run` of take.

## What was not verified

- Real devices, screen readers, Safari and Firefox. Dark themes and Sepia and Moss were audited by the accessibility walk but not looked at by a person.
- A real 429 from the PDF reader (the browser script stubs the answer; the op's own 429 is the backend's test). A book with more than 5,000 chapters, a book that reads as nothing, and a chapter over 2 MiB were not driven in a browser (their sentences are the op's).
- The fixtures are hand-made miniatures (see the backend notes): no real Sigil, Calibre, Word or PDF file was used.
- The desktop smoke test (`scripts/desktop-smoke.sh`) was not run.
- The offline check shows the application's offline notice for these pages; a typed edition label is not kept across a reload with the network cut (as with every server page).
- The diff screens were not run against a real revised book (the fixtures are generated), and the hunk viewer was looked at with a 350-difference chapter at 390 px in light and dark (seven pages of 50), not with a real book.
