# The desktop contract, as the Go side built it

This file is the contract between the Go side and the desktop shell for Phase 8. Below the rule is the contract **verbatim**, as both engineers were given it. Above it is every place where the Go side (branch `p8-desktop-go`) differs from it or had to decide something it leaves open. Each is tested; the tests are named in [desktop-go.md](desktop-go.md) and the reasons for the security choices are in [desktop-threat-model.md](desktop-threat-model.md).

## Changes and clarifications made by the Go side

What the shell must know first:

- **The shell's part is unchanged.** Spawn with `SCRIOBH_DESKTOP=1`, `SCRIOBH_LISTEN=127.0.0.1:0`, `SCRIOBH_LAUNCH_TOKEN`, `SCRIOBH_SECRET_KEY` when the keychain has one; read `LISTEN http://127.0.0.1:<port>` from stdout; poll `/healthz`; open `/desktop/start?t=<token>`; `SIGTERM` to quit. Exit status 75 with the one line `ALREADY_RUNNING` on stdout means another instance holds the data directory.
- **Open the window at `http://127.0.0.1:<port>`, never at `localhost`.** `localhost` is refused as a Host (change 10): it can resolve to `::1`, where the server does not listen.
- **Hold the server's standard input as a pipe and close it to stop the server** (change 23). It is the clean stop on every platform, and it is what stops a server whose shell was killed.
- **The port is usually the same from one launch to the next** (change 24), so the origin and what the webview keeps for it (unsaved drafts, the service worker) survive a restart. It is still read from `LISTEN`, and still not a secret.
- **An instance switched to an external provider cannot be signed in to from the window** (change 25): `/desktop/start` then shows a page with the address to open in a browser.
- **Two more normal pages exist for a menu:** `/desktop/identity` (which identity provider the instance signs in through) and `/desktop/local-model` (look for Ollama on this computer). Both are ordinary pages of the web app in desktop mode, for the administrator, which the local profile is.

Step 2 (the environment):

1. The Go side **refuses to start** in desktop mode when `SCRIOBH_BASE_URL` is set (the contract says the shell leaves it unset; the instance takes its address from the port it binds, and the Host check depends on that), when `SCRIOBH_OIDC_STUB` is on, when `SCRIOBH_OIDC_ISSUER`, `SCRIOBH_OIDC_CLIENT_ID` or `SCRIOBH_OIDC_CLIENT_SECRET` is set (an external provider is chosen in the settings, see F-390 below), and when `SCRIOBH_TRUST_PROXY` is on.
2. The listen address must be a **literal loopback IP** (`127.0.0.1:<port>` or `[::1]:<port>`); `localhost:<port>` is refused, because what a name resolves to is not this program's to decide. When `SCRIOBH_LISTEN` is not set at all, desktop mode listens on `127.0.0.1:0`.
3. The launch token must be **hexadecimal**, 32 to 256 characters. The shell's 64 fit.
4. After the server is built the process **removes `SCRIOBH_LAUNCH_TOKEN` and `SCRIOBH_SECRET_KEY` from its own environment**, so nothing it starts can inherit them. (The helper processes it starts are already given an explicit, short environment.)

Step 3 (start):

5. A second instance prints `ALREADY_RUNNING` on **stdout** and the usual sentence on stderr, and exits 75. Outside desktop mode a second instance still exits 1 with the old message and prints nothing on stdout.
6. On Windows the lock is an exclusive open of `scriobh.lock` (written, cross-compiled, **never run**).

Step 5 (`/desktop/start`):

7. **There is no lockout.** The contract's five-failures-then-a-minute rule was removed after review: the token is at least 128 bits, so counting wrong guesses protects nothing, and a limit any local program could use up only keeps the shell's own window from getting its cookie. What remains is the constant-time comparison, use once (a second use of the right token is refused like a wrong one), and an address that is never logged. `/desktop/start` also refuses (404, the token not used) a request whose `Sec-Fetch-Site` is `cross-site`, so another site's page cannot spend the token either; a request with no `Sec-Fetch-*` headers (the shell's webview, curl) works as before.
8. `/desktop/start` redirects to `/`, as written. `/` goes on to `/auth/login` by itself only for a request that carries the launch cookie, on an instance that uses the embedded issuer, whose person has not just signed out (signing out sets a small marker cookie so the sign-in page is shown instead of signing them straight back in; the next sign-in or launch clears it). Any other signed-out request for `/` gets the ordinary sign-in page.
9. A sign-in attempt without the launch cookie (`/auth/login` in a browser tab) is answered with a 403 page that says to open the application's own window, before the issuer is asked at all.

Step 6 (the issuer):

10. The **Host check applies to every route** in desktop mode, not only `/authorize`: a request whose `Host` is not exactly the bound address, `127.0.0.1:<port>` (or `[::1]:<port>` when that is what was bound), is answered `421 Misdirected Request` before any handler runs, `/healthz` and `/static/` included. **`localhost:<port>` is not accepted**, as a Host, an Origin or a redirect address, although the contract lists it: it can resolve to `::1`, where the server does not listen. (Agreed with the shell side after it ran in WKWebView.)
11. `/authorize` judges a request by **where it comes from, not by what kind it is**: `Sec-Fetch-Site` must be `same-origin`, `none` or absent, and `Origin`, when present, the instance's own. `same-site` is refused: another port of `127.0.0.1` is the same site, and cookies are not scoped to a port. `Sec-Fetch-Mode` and `Sec-Fetch-Dest` are not judged. (The first version required `Sec-Fetch-Dest: document`; in WKWebView a navigation that the application's service worker re-sends arrives as `same-origin`, `navigate`, `empty`, and the window was refused its own sign-in. A request from the instance's own origin is the application asking for itself, however it asks.) The service worker also **does not answer navigations to `/auth/`, `/desktop/` or `/desktop-idp/` at all**, so the browser makes them itself.
12. With no profile yet, `/authorize` redirects to `/desktop/profile`, and the form's success redirects to `/auth/login`, which begins a **new** authorization request. Nothing of the first request is carried through the form.
13. **The `sub` is stored in the database** (the `settings` row `desktop.profile`, with the name and the optional address), which is in the data directory, not in a file of its own: a backup holds the database and not other files, and a restore must bring the same person back. The signing key is a file, `desktop/issuer-key.json`, because it can be made again.
14. The identity stored with the account is the fixed string `urn:scriobh:desktop-profile`, not the issuer URL (which changes with the port at every launch). The client is `scriobh-desktop`, a public client with no secret; ID tokens are signed with ES256 (P-256) and live two minutes. The key is replaced when the application's version changes.
15. **The first-user rule needs two things the contract does not say.** (a) The existing rule applies only when no administrators' group is configured, and the default configuration names one; desktop mode therefore clears `SCRIOBH_ADMIN_GROUP`, and **refuses to start when the variable names a group** (an explicitly empty value is accepted). A named group would turn the rule off and refuse the local profile, which is in no group, at its first sign-in; the group that matters after a switch to an external provider is the one stored with that provider in the settings. (b) The existing rule *offers* the first user a claim on a page; in desktop mode with the embedded issuer the claim is **made for them at once**, through the same function (`Users.ClaimAdmin`, open once, recorded in `settings.admin_claimed` and in the audit log). No new rule decides who is the administrator.
16. **An account with no email address.** The existing sign-in refuses an identity with no verified address. The contract makes the address optional, so sign-in accepts an identity with no address **for the issuer string `urn:scriobh:desktop-profile` only**, and stores no address (NULL). With an address, the ordinary rule applies and the issuer marks it verified.

What the Go side exposes:

17. `GET /api/v1/desktop/info` (op `desktop.info`) answers the **administrator's browser session** (the local profile is the administrator) with `data_dir`, `version`, and also `mode` (`embedded` or `external`) and two counts: `outbound_connections` and `outbound_elsewhere`, the connections this process has opened since it started and how many of them went anywhere but this computer.
18. `SCRIOBH_DATA_DIR` unset: as written, with two details. On Linux a relative `XDG_DATA_HOME` is ignored (the XDG rule). When neither the variable nor a home directory is known the start is refused with a message that names `SCRIOBH_DATA_DIR`.

Switching to an external provider (F-390):

19. **There were no OIDC admin settings to reuse**: until now the provider came from the environment only. A page (`/desktop/identity`) and five ops (`desktop.idp.get`, `.set`, `.verify`, `.switch`, `.cancel`) were built; the client secret is sealed with the instance key in the `settings` row `desktop.idp`.
20. **The rule, which is stricter than the contract's and in a different order.** The contract links the local profile to the external identity "at first external sign-in only after they sign in as the local profile and confirm". After the restart the local profile cannot sign in any more (its issuer is not mounted), so the proof is taken **before** the switch: while signed in as the local profile, the administrator signs in at the external provider once (the same go-oidc code, the same callback); the identity that sign-in showed is recorded for that administrator and those settings; then the switch is confirmed by typing the issuer URL, and it is **made at the next start**: the local profile's account, and no other, is moved to that identity. Nothing is ever matched by email address. The proof is refused when the provider sends no verified address or when an administrators' group is named and the identity is not in it, either of which would lock the administrator out after the switch.
21. **The way back** is asked for by a signed-in administrator, confirmed by typing the local profile's name, and made at the next start: the account that was moved becomes the local profile again. **One addition to the contract:** `scriobh desktop use-local-profile`, run with the application stopped, asks for the same switch from the command line. It exists because a provider that is gone leaves nobody able to sign in to switch back; it gives nothing to anyone who could not already edit the database file.
22. An optional **fixed loopback port** can be stored with the provider, for a provider that wants one exact redirect address. When it is set and the instance signs in through the provider, the Go side binds that port instead of the `0` the shell passes, and falls back to a free one (with a warning) when it is taken. The shell reads the port from `LISTEN` either way.

After the shell ran against this binary in WKWebView (the shell side's findings, each accepted):

23. **Standard input.** In desktop mode the server stops, exactly as on `SIGTERM` (status 0, the log checkpointed), **when its standard input was a pipe at start and has reached its end**. The shell holds the other end; it closes when the shell quits, crashes or is killed, so a server never outlives its shell holding the data directory's lock. Standard input that is a terminal, `/dev/null` or closed at start never stops the server. (A socket is treated as a pipe: some launchers hand a child a socket pair for one.)
24. **The port.** With `SCRIOBH_LISTEN=127.0.0.1:0` the server binds **the port it bound last time** (kept in `desktop/port` under the data directory) and takes a free one only when that port is in use; whichever it binds is remembered. A browser keeps storage by origin, and the origin includes the port: with a new port at every launch the unsaved drafts the writing view keeps in the browser, and the service worker, were lost at every quit. When the port does change, the log says so and what the browser held for the old address is not offered at the new one; what the server saved is unaffected.
25. **An external provider and the window.** The provider's sign-in page is another site, which the shell's window does not open. So on an instance that signs in through an external provider, **the window is not the way in**: `/desktop/start` with the right token answers a signed-out window with a plain page that says so and shows the address (`http://127.0.0.1:<port>`) to open in an ordinary browser, where the sign-in completes. The application must stay open, since it is what serves the address. A window that still holds a session goes on to the library and keeps working until the session ends. Nothing was added for the shell to learn the provider's origin.
26. **Proving the provider needs a web browser too.** The sign-in that proves the provider (change 20) also leaves the application's origin. The identity page therefore makes, on request, **an address for a web browser** (`/desktop/identity/verify?ticket=<sealed>`): good once, for five minutes, for the administrator who asked. Opened in an ordinary browser, with no session and no launch cookie, it runs the sign-in at the provider there and records who that administrator is at the provider. It signs nobody in on that browser and opens nothing else; the browser is told to go back to the application, where the identity page shows the name that was proved before anything is confirmed.
27. **The sign-in addresses' own rate limit** (ten requests at once, thirty a minute, per client address) does not apply to a desktop instance on its embedded issuer: every request there comes from the one address, there is nothing to guess, and a person who signs out and in a few times was being refused. The general limit still applies.
28. **A server's database in a desktop instance.** A data directory with accounts of another provider and no account for the local profile (a restored server backup) refuses the profile's sign-in, as it must. The refusal page says what happened (the data came from a server and has its own accounts) and names `scriobh desktop use-local-profile --adopt-admin <email-or-id>`. With the application stopped, under the data directory's lock, that command binds the local profile to the one administrator account the person names, by exact id or exact email address, never by any automatic match; it is refused for a writer, a reader, an agent, a switched-off or removed account, for a name that matches no account or more than one, when the local profile already has an account, when a switch waits, and when the instance is on an external provider. It records `desktop.profile.adopt` in the audit log (no actor: it is the command line) and ends that account's browser sessions. Without `--adopt-admin` the command is as before.
29. **Confirming the switch binds the identity shown.** The identity page carries a fingerprint (a hash of issuer and subject) of the identity it shows as proved, in the switch form; `desktop.idp.switch` to the external provider takes it as `identity` and answers 409 unless it is the identity recorded now, so a second sign-in at the provider that was recorded after the page was drawn cannot be confirmed by the typed issuer URL of a page that showed someone else.

30. **`/healthz` proves the launch token to the shell, to a challenge that is new every time.** The shell sends the launch token with the start address to the port it read from `LISTEN`; `/healthz` is answered by whoever holds that port, and a server that died, with another program taking its port, would be sent the token. So in desktop mode (and in no other) `/healthz` answers a challenge. The shell sends the request header `X-Scriobh-Challenge`: a fresh 32-byte nonce from the system, as 64 lower-case hexadecimal characters, new for every check. The response carries `X-Scriobh-Proof`: 64 lower-case hexadecimal characters, `HMAC-SHA256(k, nonce)` over the nonce's 64 ASCII characters, where `k = HMAC-SHA256(key = the token's ASCII characters, message = "scriobh desktop healthz key v1")`. Only a process that holds the token can make it, it does not reveal the token (the server keeps `k`, not the token), and a proof recorded from an earlier answer is no use for the next challenge, which is why it is a challenge and not a fixed value: any local program can ask `/healthz` for a fixed value while the server lives and give it back after the port is taken. A request with no challenge, a doubled one or one that is not exactly 64 lower-case hex characters is answered as before, with no proof; the status and body are unchanged, the Host check still comes first, and nothing is added outside desktop mode. The shell requires the proof (`hmac` `verify_slice`, a constant-time comparison, on the decoded bytes, exactly one proof header) in the wait for the first good `/healthz`, where a 200 without the right proof ends the launch at once (the error window "Scríobh could not tell its own server apart", the server that was started is stopped, nothing is sent to the port), and again with a new challenge just before the window is given its address. Both sides hold the same test vector: token `5ca1ab1e` repeated eight times, nonce `00112233445566778899aabbccddeeff` repeated twice, proof `68976f01ca10fc56efcfd44364fc8a604e14f46723d71f4d717517802c04c899` (`internal/desktopidp`, `TestTheHealthzProofMatchesTheShellsVector`; `launch.rs`, `the_proof_is_the_one_the_server_makes`). Tests: `TestDesktopHealthzProvesTheToken`, `TestDesktopOffChangesNothing` (no proof outside desktop mode), the shell's `tests/launch.rs` against modes of the stand-in that answer without a proof, with a wrong one, and right once and wrong after, and `tests/real_server.rs` against the real binary. What it does not close: the instant between the last check and the window's own request to the port, and a program of the same user, which can read the server's environment (`ps eww`, `/proc/<pid>/environ`) and so answer as well as read the token itself. The proof defends against accidental reuse of a dead server's port and against other users' programs. On Windows the Go listener also takes its port with `SO_EXCLUSIVEADDRUSE`, so another program cannot share it by binding with `SO_REUSEADDR` (cross-compiled and vetted, never run). A shell look at `/healthz` ends within four seconds whatever arrives, reads only the head, and a child that exited, or was slow, is not reported as another program.

Also from the shell's fix round (not a protocol change): in desktop mode the server asks to be told of `SIGPIPE`, so a shell that is killed outright, which leaves the server's input, output and error without a reader at once, still ends in the clean stop of change 23 with the log checkpointed, instead of dying on the first log line that cannot be written (`TestDesktopSurvivesClosedOutput`).

## The shell side's header

> **This part was written on the shell branch (`p8-desktop-shell`) and kept at the merge.** The text below the rule is the contract, word for word, as both engineers were first given it. **It is not what the Go side built.** The Go branch (`p8-desktop-go`) carries the same file with its changes and clarifications on top (numbered 1 to 30); the shell is built and tested against those, and where the two disagree the Go side's list wins. What follows here is what the shell depends on from that list, what the shell does differently from the contract, and what the shell side asked for that the Go side has since done. Details and evidence are in [desktop-shell.md](desktop-shell.md).
>
> **What the shell relies on from the Go side's changes**
>
> - **`localhost` is not an app address (Go change 10).** The server answers 421 to any `Host` but `127.0.0.1:<port>`, as it does to an `Origin` or a redirect that names `localhost`; step 6 below, which lists `localhost:<port>`, is withdrawn. The shell opens the window at `127.0.0.1` and treats a `localhost` address as an ordinary outside link (`nav::is_app_url` accepts `127.0.0.1` only).
> - **No lockout (change 7).** The contract's "5 failures then a 1-minute lockout" in step 5 is gone. A wrong token is a 404 and counts for nothing; the right one is accepted once; a request with `Sec-Fetch-Site: cross-site` is refused (404) without spending it.
> - **Standard input is the shell's clean stop and its dead-man switch (change 23).** The shell holds the server's standard input as a pipe and closes it to stop the server (on Unix a `SIGTERM` follows, which is redundant with this server). A server whose standard input was a pipe at start stops itself, as on `SIGTERM`, when it reaches its end, so a shell that is killed outright no longer leaves a server behind. A standard input that is a terminal, `/dev/null` or closed never stops it.
> - **The port is kept (change 24).** `SCRIOBH_LISTEN=127.0.0.1:0` binds the port of the last run when it is free (`desktop/port` under the data folder). The shell still reads the port from `LISTEN`.
> - **The issuer judges where a request comes from, not its `Sec-Fetch-Dest` (change 11)** and the service worker leaves `/auth/`, `/desktop/` and `/desktop-idp/` alone; this is what the shell asked for when it found the sign-in refusal in WKWebView.
> - **An external provider (changes 19 to 26).** `/desktop/start` on an instance that signs in through an external provider shows a page with the address to open in an ordinary browser; the window is not the way in, and the shell does nothing about it.
> - **The environment is strict (change 1, 15).** The server refuses `SCRIOBH_BASE_URL`, a stub issuer, `SCRIOBH_OIDC_*` and `SCRIOBH_TRUST_PROXY`, and an administrators' group; the shell removes every inherited `SCRIOBH_*` name before it sets its own.
>
> **Deviations in the shell**
>
> 1. **Step 7, "the shell then focuses the first window" on exit 75.** A second copy of the app never reaches the server: the single-instance check stops it first, brings the first window to the front and hands over its arguments. Exit 75 therefore only reaches the shell when a server the app did not start holds the data folder (a server run by hand). The shell cannot focus that; it says "Scríobh is already running" and exits 0.
> 2. **Reveal in folder.** The shell has no session, so it cannot call `GET /api/v1/desktop/info`. Help, Show the Data Folder reveals the folder the shell computed by the same rule as the server (the table row "The data directory defaults"). A development build is the only one that ever sets `SCRIOBH_DATA_DIR`.
> 3. **"Opened in the system browser only after the person clicks it."** The webview does not tell the shell whether a navigation came from a click. Every outside `http`, `https` or `mailto` address is refused in the webview and a native question naming the address is put; the browser opens only if the person chooses Open. One question at a time. A `mailto:` address loses its `attach=` and `attachment=` parameters first.
> 4. **`/help` does not exist.** Help, Documentation offers the documentation address in the system browser, through the same question.
> 5. **Invariant 5 (Secrets): the keychain is not always used.** A key in the keychain is passed to the server, as written. Where passing none would make the server create a second `secret.key` over an install that has data (the keychain cannot be read, or holds something that is not a key, and the data folder has a database and no key file), the shell **does not start the server** and says so in the error window. Where the keychain holds a key and the data folder also has a `secret.key`, the file is used and the person is told once. See "The key and the keychain" in the notes.
> 6. **The server's program inside the app is `scriobh-desktop-server`**, not `scriobh`, so that it cannot collide with a server package's own file on Linux.
>
> **Asked for by the shell side, and done by the Go side** (kept here as the record of why those changes exist): the end of standard input as a stop (was proposal 1: change 23); accepting the service worker's navigation at the issuer (was proposal 2: change 11 and the worker); a way to sign in with an external provider from a browser (was proposal 3: changes 25 and 26).

# Phase 8 (v2.0 "Desktop"): the contract between the Go side and the shell

Both Phase 8 engineers build to this file. If you must change it, say so in your hand-back and change `docs/p8-notes/desktop-contract.md` in your branch (both branches carry it), do not drift silently.

## Invariants that bind this phase (AGENTS.md, do not re-litigate)

1. **OIDC only.** "The desktop build uses a real embedded OIDC issuer, never an auth bypass or a 'desktop mode' header." The embedded issuer is a real provider: discovery, JWKS, authorization endpoint with PKCE S256 and `state`/`nonce`, token endpoint, ID token verified by the same `go-oidc` client code that verifies an external IdP. The app's middleware, sessions and CSRF run unchanged.
2. **No wrapper-only feature; no filesystem bridge into the web layer; the wrapper never reaches into the database or the filesystem on the app's behalf.** Everything the desktop app can do, the web app on the same binary does too. The shell may add: native menus, native open/save dialogs for the **browser's own** file input and download flows, reveal-in-folder of a path the **server** returns for an export it wrote to the data directory, drag-and-drop through the web layer's own File API, deep links and file associations that **navigate the webview to a normal page** (never inject content or credentials).
3. **Privacy by construction.** No telemetry, no outbound request the user did not configure, the **auto-updater is the one exception and is off until the person turns it on** (it checks only a user-configured or release URL over HTTPS, sends no identifiers beyond what an HTTP request needs, verifies a minisign signature); CSP unchanged (`self` only, no inline script, **the wrapper injects nothing into the page**).
4. **The browser deployment passes its full test suite unchanged.** Desktop mode is selected only by `SCRIOBH_DESKTOP=1`; with it off nothing changes (tests prove it).
5. **Secrets**: the OS keychain holds the instance secret key (`SCRIOBH_SECRET_KEY`) which seals AI and Git secrets; the shell reads it from the keychain at launch and passes it to the sidecar by environment (never argv); if no keychain is available the existing encrypted key file in the data directory is used (as today).

## The launch protocol

The shell (Tauri, Rust) starts the Go binary as a **sidecar** and talks to it only over loopback HTTP and the process's stdio.

| Step | Who | What |
| --- | --- | --- |
| 1 | shell | Generates a **launch token**: 32 random bytes, hex. Keeps it in memory only. |
| 2 | shell | Spawns `scriobh` with env: `SCRIOBH_DESKTOP=1`, `SCRIOBH_LISTEN=127.0.0.1:0`, `SCRIOBH_LAUNCH_TOKEN=<token>`, `SCRIOBH_SECRET_KEY=<from keychain>` (when present), `SCRIOBH_DATA_DIR` (omitted: the Go side resolves the OS location itself), and `SCRIOBH_BASE_URL` unset. Never puts the token or key in argv. |
| 3 | go | Refuses to start in desktop mode without a launch token (min 32 hex chars) or on a non-loopback listen address. Takes the single-instance lock on the data directory (a second instance exits with status 75 and prints `ALREADY_RUNNING`; the shell then focuses the first window). Starts the embedded issuer on the **same** listener under `/desktop-idp/` (issuer URL = `<base>/desktop-idp`; no second port). Prints one line to stdout: `LISTEN http://127.0.0.1:<port>` (existing behaviour). |
| 4 | shell | Reads `LISTEN`, polls `GET /healthz` until 200 (timeout 30 s, then shows an error window with the sidecar's stderr tail), then opens the webview at `http://127.0.0.1:<port>/desktop/start?t=<token>`. |
| 5 | go | `GET /desktop/start?t=`: constant-time compare to the launch token; on match sets cookie `scriobh_desktop_launch=<random per-launch value derived by HMAC of the token>` (`HttpOnly`, `SameSite=Strict`, `Path=/`, `Max-Age` session, never `Secure` on http loopback) and redirects (303) to `/` (which redirects to the normal sign-in start `/auth/login`). On mismatch: 404, same body as any unknown path, and a rate limit (5 failures then a 1-minute lockout for the process). The token is accepted **once per launch** (a second valid use gets 404) and the URL is never logged. |
| 6 | go | The embedded issuer's `/authorize` **requires** the `scriobh_desktop_launch` cookie (so a browser tab, another local process or another local user that reaches the port cannot sign in), checks `Host` is `127.0.0.1:<port>` or `localhost:<port>` (DNS rebinding), refuses cross-site requests (`Sec-Fetch-Site`, `Origin`), serves **no CORS headers**, and auto-approves the **single local profile** for the one registered client (the app's own callback URL, exact match). First run: if no profile exists, `/authorize` redirects to `/desktop/profile` (a plain form: display name, optional email) which creates it (no password, no recovery: this is a local profile; say so in the page), then continues. The issued ID token has `sub = a stable random id stored in the data directory`, `email_verified=true` only if an email was given, `groups` empty; the app's first user becomes the instance admin by the existing first-user rule. |
| 7 | shell | Shows the app. Native menu items open **normal app URLs** in the same webview (`/`, `/settings`, `/import`, `/help`), the File menu's Import opens `/import`, Export opens the project's export page: **no new capability**. Closing the last window quits (macOS: quits too, as a writing tool should; keep it simple and documented). On quit: SIGTERM to the sidecar, wait up to 10 s for a clean exit, then SIGKILL. |

## What the Go side must expose (the shell relies on these, tests pin them)

- `SCRIOBH_DESKTOP=1` and `SCRIOBH_LAUNCH_TOKEN` as described; both are listed in `internal/config/env.go`'s known names (the repository test `TestEverySCRIOBHNameInTheRepositoryIsAccountedFor` requires it) and in `docs/OPERATIONS.md`.
- Exit status 75 + `ALREADY_RUNNING` for a second instance.

- The data directory defaults, when `SCRIOBH_DATA_DIR` is unset in desktop mode, to the OS location: macOS `~/Library/Application Support/Scriobh`, Linux `${XDG_DATA_HOME:-~/.local/share}/scriobh`, Windows `%AppData%\Scriobh`; created `0700`.
- The Compile/Export download flows already send `Content-Disposition: attachment`; the shell turns that into the native **save dialog** (Tauri's download handler) and never reads the file itself.

## Switching to an external IdP (F-390)

An administrator may switch an installed desktop profile to an external OIDC provider: the existing admin settings for OIDC (issuer, client id/secret sealed, groups mapping) apply; saving switches the instance to external mode **after a typed confirmation and a restart**, keeps the local profile's account (linked to the external identity by the person at first external sign-in only after they sign in as the local profile and confirm: define the safest rule: **never auto-link by email**), and the embedded issuer is no longer mounted. Switching back is possible only from a signed-in admin session. Document the rule and test it.
