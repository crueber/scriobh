Keep the secret key somewhere else

A backup does not hold the secret key, on purpose: a file with the key and your data together would give away everything at once. Copy secret.key from the data folder, or keep the value of SCRIOBH_SECRET_KEY, in a different place from your backups. If you restore without it, nothing you wrote is lost and you stay signed in, but any saved password or key for a remote repository has to be entered again.

Restoring

Restoring is a command, because it needs the server stopped. Stop it, then run scriobh restore <file> with the path of a backup. If the data folder already holds data, add --force; the command first saves what is there as a backup of its own. With Docker: docker compose run --rm scriobh restore /data/backups/<name>.zip --force. Then start the server again.

A backup over 256 MB cannot be downloaded here. Copy it from the backups folder inside the data folder.
